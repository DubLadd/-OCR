## 2026-10-06 - Configure Content Security Policy for Tesseract.js and WebAssembly
**Vulnerability:** The application was missing a Content Security Policy (CSP), leaving it open to Cross-Site Scripting (XSS) and other data injection attacks. Additionally, loading external scripts/resources (Tesseract) without CSP control is risky.
**Learning:** Tesseract.js utilizes WebAssembly for its OCR engine, requiring `'wasm-unsafe-eval'` in the `script-src` directive of the CSP. Omitting this causes browser engine evaluation failures for WebAssembly execution. It also requires `'unsafe-inline'` for some styles/scripts, `blob:` for worker/img sources, and specific origins (`cdn.jsdelivr.net`, `tessdata.projectnaptha.com`) for fetching dependencies and language data.
**Prevention:** When introducing WASM-based or Worker-based external libraries (like Tesseract.js), strictly define and review the required CSP directives (`wasm-unsafe-eval`, `blob:`, `connect-src` endpoints) instead of omitting CSP entirely or using blindly permissive configurations. Ensure test suites include a browser context capable of catching CSP violations.
