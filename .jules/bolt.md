## 2024-05-18 - Memory Leak / Fetch Error with URL.createObjectURL and Tesseract.js
**Learning:** When using `URL.createObjectURL(file)` to load an image efficiently, passing the resulting image element into Tesseract.js (`worker.recognize`) requires the object URL to remain active until the entire asynchronous OCR process completes. If `URL.revokeObjectURL()` is called prematurely (e.g., synchronously at the end of `img.onload`), Tesseract will fail internally with an `ERR_FILE_NOT_FOUND` fetch error because its WebAssembly worker tries to fetch the image data from that URL in the background.
**Action:** Always make the event handler (`img.onload`) asynchronous, `await` the OCR processing function, and only then call `URL.revokeObjectURL(url)`. This ensures peak performance without breaking the application logic.
